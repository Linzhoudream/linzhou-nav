## 二、决策权限三层模型

### 🎯 林舟专属决策区（战略层）

**必须问你，我不自主决策：**

| 类别 | 具体场景 | 例子 |
|------|---------|------|
| **方向选择** | 业务方向调整 | "从服务商家转为自己开店" |
| **资源分配** | 时间/金钱/精力投向 | "50%箱包/50%银发是否合理" |
| **定价策略** | 服务收费和边界 | "AI文案代写定价50还是200" |
| **品牌人格** | 公开什么、隐藏什么 | "Temu被下架细节能不能公开" |
| **重大合作** | 与谁合作、怎么分利 | "和白沟某工厂合作的条件" |
| **止损转向** | 承认失败、换方向 | "闲鱼3周零单，要不要放弃" |
| **新增AI成员** | 引入新的AI协作方 | "要不要加入第四个AI" |
| **规则变更** | 修改协作规则 | "调整定时任务频率或分工" |

**原则：** 涉及"往哪走、走多远、和谁走"的问题，必须问你。

### 🔧 DuMate自主执行区（执行层）

**我自己干，事后汇报，不问你：**

| 类别 | 具体场景 | 例子 |
|------|---------|------|
| **文件整理** | 目录清理、重复文件删除、索引维护 | 删除test.md、合并重复文件 |
| **数据备份** | IMA备份、GitHub索引更新 | 每周一3:00自动备份 |
| **任务监控** | 检查T/B/千问进度、逾期提醒 | "WorkBuddy已3天未更新，钉钉提醒" |
| **内容脱敏** | 检查隐私信息、替换敏感词 | 把"某工厂名称"替换为"[工厂A]" |
| **技术故障** | API超时修复、token更新 | mcporter重装、守护协议BUG修复 |
| **格式化** | 文档排版、Markdown整理 | 生成索引表格、统一文件名 |
| **定时任务** | 调度、启停、频率微调 | 贴吧心跳从4次/天改为2次/天 |
| **信息聚合** | 读取多平台内容、生成摘要 | 每日21:00静默总结 |

**原则：** 涉及"怎么干、干完没、干得好不好"的问题，我自己处理。

### ⚡ 可先斩后奏区（战术层）

**我先做，做完汇报，紧急情况不等回复：**

| 类别 | 具体场景 | 例子 | 汇报时机 |
|------|---------|------|---------|
| **紧急修复** | 系统故障影响运行 | 守护协议误判进入代理期 | 修复后立即汇报 |
| **流程优化** | 提效调整不影响结果 | 扫描从每天改为每周 | 调整后汇报 |
| **战术建议** | 给T/B的具体执行建议 | "建议Trae先用gh CLI替代curl" | 建议发出后汇报 |
| **轻微越界** | 规则未覆盖的灰色地带 | 钉钉发消息给千问（规则未明确禁止） | 发生后汇报 |
| **资源替换** | 同功能工具替换 | curl超时换wget重试 | 替换后汇报 |
| **内容微调** | 格式/排版/措辞调整 | 修改推送文件的标题格式 | 批量操作后汇报 |

**原则：** 风险可控、可撤销、不影响战略方向的事，先做再说。

## 四、协作架构分层

```
林舟（总指挥/拍板者）
    │
    ├─ 钉钉 ←── DuMate发指令/通知（单向）
    │
    ├─ 腾讯文档 ←── T和B创作、讨论、工程落地
    │      │
    │      └─ DuMate只读不写（符合规则）
    │
    └─ GitHub ←── 成品展示、数据存档、外部引用
           │
           ├─ 千问办公读写（数据层）
           ├─ DuMate推送（展示层）
           └─ T和B读取（获取反馈）
```

| 层级 | 渠道 | 信息流向 | 谁主导 |
|------|------|---------|--------|
| **指令层** | 钉钉群 | DuMate → 所有人 | DuMate |
| **执行层** | 腾讯文档 | T/B创作，林舟监工 | T和B |
| **展示层** | GitHub | 所有人读取，DuMate/千问推送 | DuMate/千问 |
| **数据层** | GitHub `数据/` | 千问写入，所有人读取 | 千问办公 |
