# 多智能体（AI）平级协作框架与定时任务规划 · 脱敏实践版

> 整理日期：2026-08-15
> 来源：一人公司「创始人 + N 个 AI 协作体」的实操复盘
> 脱敏说明：已移除所有内部文档链接 / 群组 ID / 真实姓名 / 业务数据 / 供应商信息。仅保留可复用的协作方法论。

---

## 0. 一句话结论

把"人来回传话"卸掉的**唯一可靠办法**，不是更复杂的群聊，而是：**所有 AI 把协作沉淀进一份共享文档（真相源），用收件箱 + 决策板 + 定时巡检三件套异步协同，创始人只需要在「决策板」和「结果」两处出现。**

---

## 1. 角色分工模型（平级，无层级）

| 角色 | 定位 | 核心职责 | 通道 |
|------|------|----------|------|
| 创始人 / CEO | 决策者 | 最终拍板、资源分配、方向调整 | 群 + 决策板文档 |
| 记忆中枢 Agent | 信息枢纽 | 跨会话摘要、状态追踪、盲区提醒、跨平台桥接 | 共享文档（读/写） |
| 内容运营 Agent（右手） | 内容产出 | 选题库、文案、热点、网页采集、定时编排 | 共享文档 + 即时通讯 |
| 工程实现 Agent（左手） | 动手实现 | 代码 / 出图 / 报告 / 自动化 / 数据可视化 | 共享文档 + IDE |
| 外部分析 Agent（眼睛） | 外部数据 | 第三方生态数据采集、对标分析、趋势洞察 | 第三方 IM（双向）→ 中转注入共享文档 |

**关键原则**
- AI 之间**平级分工**，CEO 永远是人。AI 不需要"代理 CEO"，需要的是**清晰边界**。
- 各自在职责范围内可独立执行，无需事事请示。
- 扬长避短：记忆中枢只做判断不做执行；内容/工程 Agent 每次启动先读「当前状态」区块补记忆。

## 2. 三大协作机制

### 2.1 收件箱文档（解决"无记忆 AI 互传消息"）
- 每个 Agent 一个收件箱文档，别人要找你就在**末尾追加**。
- 追加格式：`[交接][日期] 任务 → 接收人：X ｜ 背景 / 已完成 / 待完成 / 参考 / 注意事项 / 状态`
- 接收方在定时巡检时看到新内容，完成后在条目末尾加 `[状态：已完成]`。
- 防互覆盖三道防线：**只末尾追加 + 轻量 LOCK 标记 + 时间错开**。

### 2.2 决策板文档（只放需要人决策的事）
- 独立文档，唯一用途：收纳「需创始人拍板」的事项。
- 格式：`[待决策][日期] 标题 ｜ 背景 / 选项A / 选项B / 建议`
- 创始人每天看一次即可，不淹没在讨论里。

### 2.3 当前状态区块（无记忆 Agent 的"开机读条"）
- 记忆中枢在共享文档维护一个「当前状态 / 今日待办」区块。
- 内容/工程 Agent 每次开工**先读这块**，补齐跨会话上下文，再执行。

## 3. 定时任务规划模板

**频率原则**：固定时间、不要太频繁，节省算力；事件驱动 + 兜底巡检结合。

| 任务 | 示例时间 | 频率 | 执行者 | 说明 |
|------|----------|------|--------|------|
| 晨间全局巡检 | 08:00 | 每天 | 内容运营 | 检查各收件箱、更新状态、生成摘要 |
| 午间进度检查 | 14:30 | 每天 | 记忆中枢 | 进度扫描、错峰 |
| 晚间状态汇总 | 20:00 | 每天 | 内容运营 | 汇总当日进展、更新总览 |
| 盲区扫描 + 催办 | 21:00 | 每天 | 记忆中枢 | 触发链命中时提醒、外部 IM 催办 |
| 外部数据同步 | 08:10 | 每天 | 工程/内容 | 拉取外部分析 Agent 的新数据并注入文档 |
| 选题交叉验证 | 09:00 | 每周一、四 | 内容运营 | 多源选题库交叉验证，去重排序 |
| 生产任务执行 | 10:00 | 每周二、五 | 工程实现 | 批量产出（如出图 / 视频素材） |
| 周报汇总 | 20:00 | 每周日 | 记忆中枢 | 汇总一周进展 |

**错峰要点**（实测踩坑）
- 多个 Agent 的巡检**不要撞同一整点**，按 07:50 / 08:00 / 08:10 错开，避免同时写共享文档造成冲突与重复。
- 文档写入类任务与"辩论/轮次"类任务要用**不同自动化**承载，别共用一个任务 ID。

## 4. 防"搭框架"检验标准（最重要的一条）

> AI 协作方案不是组织架构图，是执行分工。**写完就执行。**

任何协作/产品化讨论，都必须围绕「先做出一个被市场主动认可的闭环」展开，不能滑回"又搭一遍框架"。

- 检验标准（示例）：本周创始人打 1 个电话、选 1 个款、挂 1 个链接；一周后若仍是 0 单成交，再漂亮的方案也只是"第 N 次搭框架"。
- 落地动作要小到"复制粘贴 2 分钟"，测的是「有没有人愿意掏钱」，不是「能不能运营一个店」。

---

## 5. 盲区提醒（安全阀）

记忆中枢持有创始人的「画像 + 筛子 + 踩坑模式 + 触发链」。当协作方案命中已知风险模式（如：又在大搭框架 / 怕慢创伤导致不敢动手 / 批量前没先验证 1 个样本）时，有责任主动提醒。

这不是权力，是创始人自己设定的安全阀。

## 6. 踩坑实录（为什么选"共享文档"而非"群里互聊"）

1. **即时通讯 bot 互不可见**：在同一群里，机器人之间默认互相看不到对方消息（API 设计如此，不是配置问题）。纯发不 @ = 对方实时看不到。
2. **无记忆靠文档**：跨会话记忆缺失的 Agent，靠共享文档补上下文，而不是指望自己记住。
3. **长连接会断 / 沙箱会休眠**：实时通道脆弱；异步文档持久可追溯，是更稳的真相源。
4. **代码仓库断连教训**：若依赖某代码仓库做镜像层，一旦该侧连接器断开，整条数据链就断。优先用多方都能直接访问的共享文档，代码仓库仅作可选镜像/图床。
5. **外部 Agent 通道**：外部分析 Agent 走第三方 IM 更稳，再由工程/内容 Agent 中转注入共享文档，避免强依赖单一仓库。

> 补充：业界 AI 间系统化直接通信的正解是 A2A（Agent2Agent）协议，以 AgentCard / Task / Message / 推送通知做规范总线。群聊+共享文档是轻量务实版，扩更多协作者时可平滑升级到完整 A2A SDK。

## 7. 通用方法论（可迁移技巧）

### 7.1 出图 prompt「SPEC 钉死」法
避免"提示词写得专业、图却不对货"：把产品属性**写死**再出图——
- 形状 / 材质 / 闭合方式 / 尺寸 四项必写死；
- 配件（如挂件）须钉「造型 + 尺寸 + 材质 + 挂法」；
- 口袋等结构尽量量化；
- 配色用品类真实色，标注"概念非现货"（仅测款线）；
- 版权红线：禁具体 IP，统一"原创潮玩 / 同源挂件"表述；
- 出图走外部工具，**必须人工二审版权与合规后发布**。

### 7.2 选题 / 内容评分模型（权重模板）
综合分 = 爆款概率×0.30 + 钩子×0.20 + 天花板×0.25 + 护城河×0.15 + 可行性×0.10。
（权重可按行业调整，关键是把"护城河/差异化"与"可行性"都纳入，避免只追热度。）

### 7.3 多源交叉验证
把多个 Agent / 多个选题库逐条比对，取"两边独立提出 + 优先级高 + 锚点数据真实 + 尚未辩过"的议题排序，减少重复建设。
